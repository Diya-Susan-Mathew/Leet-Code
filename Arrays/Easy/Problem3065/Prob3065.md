# Minimum Operations to Make All Elements Greater Than or Equal to `k`

## 1. Understand the problem

You are given: - An integer array `nums`. - An integer `k`.

The goal is to make **every element in the array greater than or equal
to `k`** using the minimum number of operations.

For this problem, one operation means removing one element that is
smaller than `k`.

So, we need to count how many elements satisfy:

``` java
nums[i] < k
```

Each such element needs exactly one operation.

------------------------------------------------------------------------

## 2. Example walkthrough

### Example 1

``` text
nums = [2, 1, 5, 3]
k = 3
```

Our target is to make every element greater than or equal to `3`.

**Step 1: Check each element.**

  Element   Is it smaller than 3?   Operation needed?
  --------- ----------------------- -------------------
  2         Yes                     Yes
  1         Yes                     Yes
  5         No                      No
  3         No                      No

**Step 2: Count the elements smaller than `k`.**

The elements smaller than `3` are `2` and `1`.

Therefore, we need two operations.

**Step 3: Remove those elements.**

``` text
Original array: [2, 1, 5, 3]

After removing 2: [1, 5, 3]

After removing 1: [5, 3]
```

Now every remaining element is greater than or equal to `3`.

**Answer: `2`**

### Example 2

``` text
nums = [1, 2, 3, 4, 5]
k = 4
```

The elements smaller than `4` are:

``` text
1, 2, 3
```

We need three operations to remove them.

Remaining array:

``` text
[4, 5]
```

**Answer: `3`**

### Example 3

``` text
nums = [5, 6, 7, 8]
k = 3
```

All elements are already greater than or equal to `3`.

No operations are required.

**Answer: `0`**

------------------------------------------------------------------------

## 3. Approach 1: Sorting

``` java
class Solution {
    public int minOperations(int[] nums, int k) {
        Arrays.sort(nums);

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] >= k) {
                return i;
            }
        }

        return nums.length;
    }
}
```

### Explanation

1.  Sort the array in ascending order.
2.  After sorting, all elements smaller than `k` will appear before the
    elements greater than or equal to `k`.
3.  Traverse the sorted array.
4.  When the first element greater than or equal to `k` is found at
    index `i`, all `i` elements before it are smaller than `k`.
5.  Return `i`.
6.  If no element is greater than or equal to `k`, every element is
    smaller than `k`, so return `nums.length`.

### Dry run

``` text
nums = [2, 1, 5, 3]
k = 3

After sorting:
[1, 2, 3, 5]

i = 0 -> nums[0] = 1 -> 1 < 3
i = 1 -> nums[1] = 2 -> 2 < 3
i = 2 -> nums[2] = 3 -> 3 >= 3

Return i = 2
```

**Complexity analysis**

-   **Time Complexity:** `O(n log n)` for sorting, followed by `O(n)`
    traversal. Overall: `O(n log n)`.
-   **Auxiliary Space:** Depends on the sorting implementation used by
    Java; `Arrays.sort(int[])` may use additional stack space.

------------------------------------------------------------------------

## 4. Approach 2: Counting

``` java
class Solution {
    public int minOperations(int[] nums, int k) {
        int count = 0;

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] < k) {
                count++;
            }
        }

        return count;
    }
}
```

### Explanation

1.  Initialize `count` to `0`.
2.  Traverse the array once.
3.  Check whether each element is smaller than `k`.
4.  If it is, increment `count`.
5.  Return `count` after the traversal.

There is no need to sort the array because we only need to count the
elements smaller than `k`.

### Dry run

``` text
nums = [2, 1, 5, 3]
k = 3

count = 0

i = 0 -> nums[0] = 2 -> 2 < 3 -> count = 1
i = 1 -> nums[1] = 1 -> 1 < 3 -> count = 2
i = 2 -> nums[2] = 5 -> 5 < 3 is false
i = 3 -> nums[3] = 3 -> 3 < 3 is false

Return count = 2
```

**Complexity analysis**

-   **Time Complexity:** `O(n)` because the array is traversed exactly
    once.
-   **Auxiliary Space:** `O(1)` because only one extra variable
    (`count`) is used.

------------------------------------------------------------------------

## 6. Which approach is better?

**Approach 2 (Counting) is better.**

Sorting is unnecessary because the required answer depends only on how
many elements are smaller than `k`, not on their order.

The second approach: - Takes linear time, `O(n)`. - Uses constant
auxiliary space, `O(1)`. - Does not modify the input array by sorting
it.

## 7. Key learning

Before sorting an array, ask yourself:

> Do I actually need the elements to be in order, or do I only need to
> count or check something?

If the task only requires counting elements that satisfy a condition, a
single traversal is usually enough.
