# Get Sneaky Numbers -- HashSet vs Boolean Array

This note compares two approaches for finding the two repeated numbers
in an integer array.

## 1. My Own Solution -- Using HashSet

``` java
class Solution {
    public int[] getSneakyNumbers(int[] nums) {
        int j = 0;
        int[] arr = new int[2];
        Set<Integer> set = new HashSet<>();

        for (int i = 0; i < nums.length; i++) {
            if (!set.contains(nums[i])) {
                set.add(nums[i]);
            } else {
                arr[j] = nums[i];
                j++;
            }
        }

        return arr;
    }
}
```

### Explanation

-   `HashSet<Integer>` stores the numbers that have already appeared.
-   For each number, `set.contains(nums[i])` checks whether it is
    already present.
-   If it is not present, add it to the set.
-   If it is already present, it is a duplicate. Store it in `arr`.
-   Return the result array containing the two repeated numbers.

## 2. Alternative Solution -- Using a Boolean Array

``` java
class Solution {
    public int[] getSneakyNumbers(int[] nums) {
        int j = 0;
        int[] arr = new int[2];
        boolean[] visited = new boolean[nums.length];

        for (int i = 0; i < nums.length; i++) {
            if (!visited[nums[i]]) {
                visited[nums[i]] = true;
            } else {
                arr[j++] = nums[i];
            }
        }

        return arr;
    }
}
```

**Correction:** The provided alternative had a typo, `nuams[i]`. It
should be `nums[i]`.

### Explanation

-   `visited` is a Boolean array. Every element is initially `false`.
-   The value `visited[x]` tells us whether number `x` has appeared
    before.
-   If `visited[nums[i]]` is `false`, mark it `true`.
-   Otherwise, the number has appeared before, so store it in `arr`.

This approach assumes every value in `nums` is a valid index for
`visited`. For example, if `visited` has length `nums.length`, each
number must be in the range `0` to `nums.length - 1`.

## 3. Dry Run

Input:

``` java
nums = [0, 1, 1, 0]
```

Initially:

``` java
visited = [false, false, false, false]
arr = [0, 0]
```

  `nums[i]`   Check                   Action                     `arr`
  ----------- ----------------------- -------------------------- ----------
  0           `visited[0] == false`   Mark `visited[0] = true`   `[0, 0]`
  1           `visited[1] == false`   Mark `visited[1] = true`   `[0, 0]`
  1           `visited[1] == true`    Store duplicate            `[1, 0]`
  0           `visited[0] == true`    Store duplicate            `[1, 0]`

Output:

``` java
[1, 0]
```

## 4. Complexity Analysis

Let `n` be the length of the input array.

  Approach        Time Complexity   Auxiliary Space
  --------------- ----------------- -----------------
  HashSet         O(n) average      O(n)
  Boolean array   O(n)              O(n)

Both approaches process each element once and use additional storage
proportional to the input size.

## 5. Comparison

  -----------------------------------------------------------------------
  HashSet                             Boolean Array
  ----------------------------------- -----------------------------------
  Stores the actual values            Stores whether a value has appeared

  Works with arbitrary integer values Requires values to fit the array's
                                      index range

  Uses a collection                   Uses a simple array

  Average O(1) lookup                 O(1) lookup
  -----------------------------------------------------------------------

## 6. Key Takeaway

Both solutions are efficient and have O(n) time complexity.

-   Use **HashSet** when the input values can be arbitrary integers.
-   Use a **Boolean array** when the values are within a known, small
    index range.

The Boolean array avoids hashing, but it is not universally better: its
size and valid index range must be suitable for the input.

**Assumption for both snippets:** The problem guarantees exactly two
duplicate occurrences to store. If more than two repeated occurrences
are encountered, the fixed-size result array can cause an
`ArrayIndexOutOfBoundsException`.
