# Finding Missing Elements in an Array — Java

## 1. My Original Approach: Using `ArrayList`

```java
class Solution {
    public List<Integer> findMissingElements(int[] nums) {
        int max = Integer.MIN_VALUE;
        int min = Integer.MAX_VALUE;

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] > max) {
                max = nums[i];
            }
            if (nums[i] < min) {
                min = nums[i];
            }
        }

        ArrayList<Integer> list1 = new ArrayList<>();

        for (int i = 0; i < nums.length; i++) {
            list1.add(nums[i]);
        }

        ArrayList<Integer> list = new ArrayList<>();

        for (int i = min; i <= max; i++) {
            if (!list1.contains(i)) {
                list.add(i);
            }
        }

        return list;
    }
}
```

### How it works

1. Find the minimum and maximum values in the array.
2. Copy the array elements into an `ArrayList` called `list1`.
3. Check every integer from `min` to `max`.
4. If `list1` does not contain the integer, add it to the result list.
5. Return the result list.

### Example

Input:

```text
nums = [1, 4, 2, 6]
```

- Minimum = `1`
- Maximum = `6`
- Numbers checked: `1, 2, 3, 4, 5, 6`
- Missing numbers: `3, 5`

Output:

```text
[3, 5]
```

### Why is this approach slower?

`ArrayList.contains()` may check every element until it finds a match. Its worst-case time complexity is **O(n)**.

Let:
- `n` = number of elements in the input array
- `R` = size of the range from `min` to `max`, inclusive (`max - min + 1`)

The overall time complexity is **O(n + Rn)**.

The extra space complexity is **O(n + R)**, including the stored input elements and the result list.

## 2. Optimized Approach: Using `HashSet`

```java
import java.util.*;

class Solution {
    public List<Integer> findMissingElements(int[] nums) {
        int max = Integer.MIN_VALUE;
        int min = Integer.MAX_VALUE;

        for (int num : nums) {
            max = Math.max(max, num);
            min = Math.min(min, num);
        }

        HashSet<Integer> set = new HashSet<>();

        for (int num : nums) {
            set.add(num);
        }

        ArrayList<Integer> list = new ArrayList<>();

        for (int i = min; i <= max; i++) {
            if (!set.contains(i)) {
                list.add(i);
            }
        }

        return list;
    }
}
```

### How it works

1. Find the minimum and maximum values.
2. Add all array elements to a `HashSet`.
3. Check each integer between `min` and `max`.
4. If the set does not contain the integer, add it to the result list.
5. Return the result list.

### What is a `HashSet`?

A `HashSet` stores unique elements and supports membership checks in **O(1) average time**.

For example:

```java
HashSet<Integer> set = new HashSet<>();

set.add(1);
set.add(4);
set.add(2);
set.add(6);

System.out.println(set.contains(3)); // false
System.out.println(set.contains(4)); // true
```

### What changed from my original code?

**Original approach:**

```java
ArrayList<Integer> list1 = new ArrayList<>();

for (int i = 0; i < nums.length; i++) {
    list1.add(nums[i]);
}

// Later:
if (!list1.contains(i)) {
    list.add(i);
}
```

**HashSet approach:**

```java
HashSet<Integer> set = new HashSet<>();

for (int num : nums) {
    set.add(num);
}

// Later:
if (!set.contains(i)) {
    list.add(i);
}
```

The main change is replacing `ArrayList` with `HashSet` for membership checks. The overall algorithm stays the same.

## 3. Complexity Comparison

| Operation | `ArrayList` approach | `HashSet` approach |
|---|---:|---:|
| Find minimum and maximum | O(n) | O(n) |
| Store input elements | O(n) | O(n) average |
| Check the range for missing values | O(Rn) | O(R) average |
| **Overall time complexity** | **O(n + Rn)** | **O(n + R)** average |
| **Extra space complexity** | **O(n + R)** | **O(n + R)** |

Here, `R = max - min + 1`.

The HashSet approach is faster on average because checking whether an element exists is typically O(1), rather than O(n).

## 4. Important Observations

- Your original logic is correct.
- Both code snippets in the original question were identical; the second one did not yet use a `HashSet`.
- The loop checks values in increasing order, so the missing elements are already returned in ascending order. No sorting is needed.
- A `HashSet` does not store duplicate values, which is fine here because we only need to know whether a value exists.
- If the range between the minimum and maximum is extremely large, iterating through every number in that range can still be expensive.

## Key Takeaway

**Use an `ArrayList` when you need an ordered, index-based collection. Use a `HashSet` when you frequently need to check whether an element exists.**
