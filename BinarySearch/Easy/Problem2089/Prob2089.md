# LeetCode 2089: Find Target Indices After Sorting Array

## Problem

Given an integer array `nums` and an integer `target`, sort the array in non-decreasing order and return all indices where the value equals `target`.

This file compares two approaches:
1. **Your approach:** Sort the array and scan every element.
2. **Counting approach:** Sort the array, count elements smaller than `target` and count occurrences of `target`, then construct the indices.

> Note: The second solution is not a binary search approach. It still scans the sorted array using a loop. A true binary search solution would use binary search to find the first and/or last occurrence of `target`.

---

## Approach 1: Sort and Scan (My Approach)

### Java Code

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<Integer> targetIndices(int[] nums, int target) {
        Arrays.sort(nums);

        List<Integer> list = new ArrayList<>();

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == target) {
                list.add(i);
            }
        }

        return list;
    }
}
```

### Explanation

1. `Arrays.sort(nums)` sorts the array in ascending order.
2. Create an empty list to store the target indices.
3. Traverse every index in the sorted array.
4. If `nums[i] == target`, add index `i` to the list.
5. Return the list.

### Complexity

- **Time:** `O(n log n)` for sorting plus `O(n)` for scanning, so overall `O(n log n)`.
- **Space:** Up to `O(n)` for the result list, excluding sorting-related space.

## Approach 2: Count Smaller Elements and Target Frequency

### Java Code

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<Integer> targetIndices(int[] nums, int target) {
        Arrays.sort(nums);

        int lessCount = 0;
        int freq = 0;

        for (int num : nums) {
            if (num < target) {
                lessCount++;
            } else if (num == target) {
                freq++;
            }
        }

        List<Integer> result = new ArrayList<>();

        for (int i = 0; i < freq; i++) {
            result.add(lessCount + i);
        }

        return result;
    }
}
```

### Explanation

#### 1. Sort the array

```java
Arrays.sort(nums);
```

Sorting puts smaller numbers first, followed by the target values.

#### 2. Count numbers smaller than the target and count target occurrences

```java
int lessCount = 0;
int freq = 0;

for (int num : nums) {
    if (num < target) {
        lessCount++;
    } else if (num == target) {
        freq++;
    }
}
```

- `lessCount` is the number of elements smaller than `target`.
- `freq` is the number of times `target` appears.

Because the array is sorted, the first index of `target` is `lessCount`. If the target appears `freq` times, its indices are:

`lessCount`, `lessCount + 1`, ..., `lessCount + freq - 1`.

#### 3. Construct the result indices

```java
for (int i = 0; i < freq; i++) {
    result.add(lessCount + i);
}
```

This adds each index where the target appears, without scanning the array again by index.

#### 4. Return the result

```java
return result;
```

### Example Walkthrough

Input:

```text
nums = [1, 2, 5, 2, 3]
target = 2
```

After sorting:

```text
[1, 2, 2, 3, 5]
```

- `lessCount = 1` because only `1` is smaller than `2`.
- `freq = 2` because `2` appears twice.
- Result indices: `1 + 0 = 1` and `1 + 1 = 2`.

Output:

```text
[1, 2]
```

### Complexity

- **Time:** `O(n log n)` for sorting and `O(n)` for counting. Overall: `O(n log n)`.
- **Space:** Up to `O(n)` for the result list, excluding sorting-related space.

---

## Is Approach 2 Binary Search?

No. Although it avoids the second full scan, it still uses a `for-each` loop to inspect every array element. Therefore, it is a **counting approach**, not binary search.

A true binary search approach can find the first index whose value is greater than or equal to `target` and the first index whose value is greater than `target`. These positions identify the target's indices after sorting.

## Key Takeaway

- **Approach 1:** Directly collect indices where `nums[i] == target`.
- **Approach 2:** Count smaller elements and target occurrences, then generate the consecutive indices.
- **Both approaches:** Have `O(n log n)` time complexity because they sort the array.
