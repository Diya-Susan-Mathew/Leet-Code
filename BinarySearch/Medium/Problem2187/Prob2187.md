# LeetCode 2187 — Minimum Time to Complete Trips

## Problem

You are given an array `time`.

```text
time[i]
```

represents the amount of time taken by the `i-th` bus to complete **one trip**.

All buses operate **independently and simultaneously**.

Given:

```text
totalTrips
```

find the **minimum amount of time** needed for all buses together to complete at least `totalTrips`.

---

# Example

```text
time = [1, 2, 3]
totalTrips = 5
```

The buses take:

```text
Bus 1 → 1 minute per trip
Bus 2 → 2 minutes per trip
Bus 3 → 3 minutes per trip
```

Suppose we have `3` minutes.

Trips completed:

```text
Bus 1 → 3 / 1 = 3 trips
Bus 2 → 3 / 2 = 1 trip
Bus 3 → 3 / 3 = 1 trip
```

Total:

```text
3 + 1 + 1 = 5 trips
```

Therefore:

```text
Answer = 3
```

---

# Main Idea: Binary Search on Answer

We are **not searching for an element** in the array.

Instead, we are searching for the **minimum possible time**.

This is called:

> **Binary Search on Answer**

We search over a range of possible times.

```text
left ---------------------- right
          ↑
     possible answer
```

For every `mid`, we ask:

> Can all buses complete at least `totalTrips` within `mid` minutes?

If YES:

```text
mid is possible
```

We try to find an even smaller time.

If NO:

```text
mid is not possible
```

We need more time.

---

# Step 1: Find `left`

The fastest bus determines the earliest possible answer.

```java
long left = Integer.MAX_VALUE;

for (int i = 0; i < time.length; i++) {

    if (time[i] < left) {
        left = time[i];
    }
}
```

We can think of this as:

```text
left = minimum value in time[]
```

### Why can't the answer be smaller than the fastest bus?

Suppose:

```text
time = [2, 3, 7]
```

The fastest bus needs `2` minutes for one trip.

So we cannot complete even **one trip** in less than `2` minutes.

Therefore:

```text
left = 2
```

---

# Step 2: Find `right`

The slowest possible situation is when we use the fastest bus to complete all trips by itself.

If:

```text
fastest bus = 2
totalTrips = 5
```

then:

```text
2 × 5 = 10
```

So:

```java
long right = totalTrips * left;
```

### Why is this a valid upper bound?

Because the fastest bus alone can complete:

```text
totalTrips
```

in:

```text
fastest time × totalTrips
```

We might be able to finish earlier by using all the buses, but we know the answer **cannot be greater than this**.

---

# Step 3: Calculate `mid`

```java
long mid = left + (right - left) / 2;
```

This is safer than:

```java
(left + right) / 2
```

because `left + right` could potentially overflow.

---

# Step 4: Check Whether `mid` Is Possible

We need to determine:

> How many trips can all buses complete in `mid` minutes?

For one bus:

```text
time available / time per trip
```

So:

```text
mid / time[i]
```

gives the number of trips that bus can complete.

For example:

```text
mid = 10
time[i] = 3
```

Then:

```text
10 / 3 = 3 trips
```

because integer division is used.

For all buses:

```java
total += mid / time[i];
```

---

# `isPossible()` Function

```java
public boolean isPossible(int[] time, int totalTrips, long tripTime) {

    long total = 0;

    for (int i = 0; i < time.length; i++) {

        total += tripTime / time[i];
    }

    return total >= totalTrips;
}
```

If:

```text
total >= totalTrips
```

then `tripTime` is enough.

Otherwise, we need more time.

---

# Binary Search Logic

### If `mid` is possible

```java
if (isPossible(time, totalTrips, mid)) {

    right = mid - 1;

}
```

Why?

Because `mid` works, but there might be a smaller answer.

So search the left half:

```text
left -------- mid -------- right
             ✓

Search:
left ----- right
```

---

### If `mid` is NOT possible

```java
else {

    left = mid + 1;

}
```

Why?

Because `mid` is too small.

We need more time.

So search the right half:

```text
left -------- mid -------- right
             ✗

Search:
                 left ---- right
```

---

# Complete Code

```java
class Solution {

    public long minimumTime(int[] time, int totalTrips) {

        long left = Integer.MAX_VALUE;

        for (int i = 0; i < time.length; i++) {

            if (time[i] < left) {
                left = time[i];
            }
        }

        long right = totalTrips * left;

        while (left <= right) {

            long mid = left + (right - left) / 2;

            if (isPossible(time, totalTrips, mid)) {

                right = mid - 1;

            } else {

                left = mid + 1;
            }
        }

        return left;
    }

    public boolean isPossible(int[] time, int totalTrips, long tripTime) {

        long total = 0;

        for (int i = 0; i < time.length; i++) {

            total += tripTime / time[i];
        }

        return total >= totalTrips;
    }
}
```

# Why Does Binary Search Work?

The important property is **monotonicity**.

As time increases, the number of trips we can complete **never decreases**.

For example:

```text
Time       Trips possible
1          1
2          3
3          5
4          6
5          8
...
```

Once a certain amount of time becomes sufficient, **every larger amount of time is also sufficient**.

So we have:

```text
Not Possible | Possible
-------------|----------------
      ❌     |      ✅
      ❌     |      ✅
      ❌     |      ✅
               ↑
          Minimum possible
```

This is exactly the type of problem where **Binary Search on Answer** can be used.

---

# Important Pattern

Whenever you see:

> Find the minimum/maximum value such that a condition is satisfied.

Ask:

### 1. Can I define a range of possible answers?

```text
left → smallest possible answer
right → largest possible answer
```

### 2. Can I check whether `mid` works?

```text
isPossible(mid)
```

### 3. Is the condition monotonic?

For example:

```text
❌ ❌ ❌ ❌ ✅ ✅ ✅
```

If yes, binary search may work.

---

# Common Mistake: Why Isn't `left` the Maximum Value?

Suppose:

```text
time = [2, 3, 7]
```

You might think:

```text
left = 7
```

because `7` is the maximum.

But that would be incorrect.

The question is asking for the **minimum time needed**.

The fastest bus takes only `2` minutes for one trip.

So an answer smaller than `2` is impossible, but an answer starting from `2` is possible.

Therefore:

```text
left = minimum(time)
```

not:

```text
left = maximum(time)
```

---

# Why Is `right = totalTrips × minimumTime`?

Suppose:

```text
minimumTime = 2
totalTrips = 5
```

Even if all other buses were ignored, the fastest bus can complete:

```text
5 trips × 2 minutes
```

in:

```text
10 minutes
```

Therefore, `10` is definitely enough.

The actual answer may be much smaller because **all buses work simultaneously**.

So:

```text
right = totalTrips × fastest bus time
```

is a safe upper bound.

---

# Overflow Consideration

Use `long` instead of `int` for:

```java
long left;
long right;
long mid;
long total;
```

because the answer can become very large.

Also:

```java
long right = totalTrips * left;
```

is safe here because `left` is a `long`, so the multiplication is performed as `long`.

---

# Complexity

Let:

* `n` = number of buses
* `T` = value of the upper bound

For every binary-search iteration, we loop through all buses.

Number of binary-search iterations:

```text
O(log T)
```

Each `isPossible()` call:

```text
O(n)
```

Therefore:

```text
Time Complexity = O(n log T)
```

Space:

```text
Space Complexity = O(1)
```

# Alternative Way to Find `left`

Instead of:

```java
long left = Integer.MAX_VALUE;

for (int i = 0; i < time.length; i++) {

    if (time[i] < left) {
        left = time[i];
    }
}
```

you can use:

```java
long left = time[0];

for (int t : time) {
    left = Math.min(left, t);
}
```

This is shorter and easier to read.

---

# Cleaner Version

```java
class Solution {

    public long minimumTime(int[] time, int totalTrips) {

        long left = time[0];

        for (int t : time) {
            left = Math.min(left, t);
        }

        long right = totalTrips * left;

        while (left <= right) {

            long mid = left + (right - left) / 2;

            if (isPossible(time, totalTrips, mid)) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }

        return left;
    }

    public boolean isPossible(int[] time, int totalTrips, long tripTime) {

        long total = 0;

        for (int t : time) {
            total += tripTime / t;
        }

        return total >= totalTrips;
    }
}
```

# DSA Pattern to Remember

## Binary Search on Answer

```text
Find minimum time
       ↓
Find possible range
       ↓
left = minimum possible
right = maximum possible
       ↓
Calculate mid
       ↓
Can mid satisfy the requirement?
       ↓
   YES          NO
    ↓            ↓
Move right    Move left
    ↓            ↓
Try smaller   Need more
answer        time
```

### The Core Template

```java
while (left <= right) {

    long mid = left + (right - left) / 2;

    if (isPossible(mid)) {
        right = mid - 1;
    } else {
        left = mid + 1;
    }
}

return left;
```

## Key Takeaway

The most important thing to recognize in this problem is:

> **We are binary-searching the answer, not the array.**

The combination to remember is:

```text
Minimum/Maximum answer
        +
Can check if mid works
        +
Monotonic condition
        ↓
Binary Search on Answer
```
