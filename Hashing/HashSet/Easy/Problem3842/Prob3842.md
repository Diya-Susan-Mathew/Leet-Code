# Toggle Light Bulbs

## Problem

You are given a list of bulbs. Each number represents a bulb that is toggled.

* If a bulb is **OFF**, toggling it turns it **ON**.
* If a bulb is **ON**, toggling it turns it **OFF**.
* Return the bulbs that are ON in **sorted order**.

---

## Example

### Input

```text
bulbs = [1, 2, 1, 3, 2]
```

### Dry Run

| Bulb | Operation | Set      |
| ---- | --------- | -------- |
| 1    | Add 1     | `[1]`    |
| 2    | Add 2     | `[1, 2]` |
| 1    | Remove 1  | `[2]`    |
| 3    | Add 3     | `[2, 3]` |
| 2    | Remove 2  | `[3]`    |

### Output

```text
[3]
```

Bulbs `1` and `2` were toggled twice, so they are OFF.

Bulb `3` was toggled once, so it is ON.

---

# Approach 1: TreeSet

## Idea

Use a `TreeSet` to store the bulbs that are currently **ON**.

For every bulb:

* If it already exists → remove it → bulb becomes OFF.
* If it doesn't exist → add it → bulb becomes ON.

A `TreeSet` automatically keeps elements **sorted**.

### Code

```java
class Solution {
    public List<Integer> toggleLightBulbs(List<Integer> bulbs) {

        Set<Integer> set = new TreeSet<>();

        for (int bulb : bulbs) {
            if (set.contains(bulb)) {
                set.remove(bulb);
            } else {
                set.add(bulb);
            }
        }

        return new ArrayList<>(set);
    }
}
```

---

# Improved TreeSet Version

We don't actually need to use `contains()`.

`remove()` returns:

* `true` → element existed and was removed
* `false` → element didn't exist

Therefore:

```java
class Solution {
    public List<Integer> toggleLightBulbs(List<Integer> bulbs) {

        Set<Integer> set = new TreeSet<>();

        for (int bulb : bulbs) {
            if (!set.remove(bulb)) {
                set.add(bulb);
            }
        }

        return new ArrayList<>(set);
    }
}
```

### Why does this work?

Suppose:

```text
Set = [1, 2, 3]
bulb = 2
```

`set.remove(2)` returns `true`.

So:

```text
Set = [1, 3]
```

The bulb was ON → now OFF.

---

Suppose:

```text
Set = [1, 3]
bulb = 2
```

`set.remove(2)` returns `false`.

Therefore:

```java
set.add(2);
```

Now:

```text
Set = [1, 2, 3]
```

The bulb was OFF → now ON.

# Approach 2: HashSet + Sorting

We can also use a `HashSet`.

A `HashSet` provides faster average insertion and removal than a `TreeSet`, but it **doesn't maintain sorted order**.

So after processing all bulbs, we convert the set into a list and sort it.

### Code

```java
class Solution {
    public List<Integer> toggleLightBulbs(List<Integer> bulbs) {

        Set<Integer> set = new HashSet<>();

        for (int bulb : bulbs) {
            if (!set.remove(bulb)) {
                set.add(bulb);
            }
        }

        List<Integer> result = new ArrayList<>(set);
        Collections.sort(result);

        return result;
    }
}
```

### Complexity

Let:

* `n` = number of bulbs
* `k` = number of different bulbs remaining ON

HashSet operations take **O(1) average**.

Sorting takes:

```text
O(k log k)
```

Therefore:

```text
Time:  O(n + k log k)
Space: O(k)
```

# Approach 3: Frequency Counting

There is another possible approach if the bulb numbers are within a **small known range**.

Instead of a Set, we can count how many times each bulb appears.

A bulb is ON if it appears an **odd number of times**.

For example:

```text
[1, 2, 1, 3, 2]
```

Frequencies:

```text
1 → 2 times → OFF
2 → 2 times → OFF
3 → 1 time  → ON
```

So the answer is:

```text
[3]
```

The important observation is:

> A bulb toggled an even number of times is OFF.
> A bulb toggled an odd number of times is ON.

If the maximum bulb number is small, we could use an array:

```java
int[] count = new int[maxBulb + 1];

for (int bulb : bulbs) {
    count[bulb]++;
}

List<Integer> result = new ArrayList<>();

for (int i = 1; i <= maxBulb; i++) {
    if (count[i] % 2 == 1) {
        result.add(i);
    }
}
```

### Complexity

If `M` is the maximum bulb number:

```text
Time:  O(n + M)
Space: O(M)
```

However, this approach is **not ideal when bulb numbers can be very large**, because the array would become unnecessarily large.

---

# Which Approach Should You Use?

| Approach         |           Time | Sorted Automatically? | When to Use                   |
| ---------------- | -------------: | :-------------------: | ----------------------------- |
| `TreeSet`        |     O(n log k) |           ✅           | Simple and clean              |
| `HashSet + sort` | O(n + k log k) |           ❌           | Faster average set operations |
| Frequency array  |       O(n + M) |           ✅           | Small bounded bulb values     |

# Best Approach for This Problem

The **TreeSet approach is probably the cleanest** because the problem requires the answer in sorted order.

The improved version is especially neat:

```java
class Solution {
    public List<Integer> toggleLightBulbs(List<Integer> bulbs) {

        Set<Integer> set = new TreeSet<>();

        for (int bulb : bulbs) {
            if (!set.remove(bulb)) {
                set.add(bulb);
            }
        }

        return new ArrayList<>(set);
    }
}
```

# DSA Pattern to Remember

## Toggle an Element Using a Set

Whenever an element needs to switch between two states every time it appears:

```java
if (set.contains(x)) {
    set.remove(x);
} else {
    set.add(x);
}
```

Or the shorter version:

```java
if (!set.remove(x)) {
    set.add(x);
}
```

### Meaning

```text
Exists → Remove
Doesn't exist → Add
```

This pattern is useful for problems involving:

* Toggle operations
* ON/OFF states
* Odd/even occurrences
* Elements appearing repeatedly
* Finding elements that occur an odd number of times

---

# Important Observation

Another way to think about the problem is:

> **Only the parity (odd/even count) of each bulb matters.**

```text
1 occurrence → ON
2 occurrences → OFF
3 occurrences → ON
4 occurrences → OFF
...
```

So:

```text
Odd frequency  → ON
Even frequency → OFF
```

This observation can help you recognize similar problems in the future.

When you see:

Think:

Frequency / Parity
