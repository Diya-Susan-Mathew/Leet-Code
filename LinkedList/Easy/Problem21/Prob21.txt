Problem Name: Merge Two Sorted Lists

LeetCode No: 21

Difficulty: Easy

Pattern Used:
Linked List / Dummy Node

Problem Statement:
You are given the heads of two sorted linked lists list1 and list2.

Merge the two lists into one sorted list. The list should be made by splicing together the nodes of the first two lists.

Return the head of the merged linked list.

Example:

Input:
list1 = [1,2,4]
list2 = [1,3,4]

Output:
[1,1,2,3,4,4]

--------------------------------------------------

Optimal Approach

Pattern:
Dummy Node + Two Pointers

Idea:

1. Create a dummy node to keep track of the head of the merged list.
2. Create a current pointer to build the merged list.
3. Compare the current nodes of list1 and list2.
4. Attach the smaller node to the merged list.
5. Move the corresponding list pointer forward.
6. Move current forward.
7. Repeat until one list becomes empty.
8. Attach the remaining nodes of the non-empty list.
9. Return dummy.next.

Code:
(Java code in Problem21.java)

Time Complexity: O(m + n)

Space Complexity: O(1)

where:
m = length of list1
n = length of list2

--------------------------------------------------

Key Observation

Since both linked lists are already sorted:

- The smallest available element is always at the current head of either list1 or list2.
- We only need to compare the current nodes of the two lists.
- No extra nodes need to be created.
- We simply rearrange the next pointers.

--------------------------------------------------

Dry Run

Input:

list1 = 1 → 2 → 4
list2 = 1 → 3 → 4

Initial:

dummy → null
current = dummy

Step 1:

Compare 1 and 1

Take list1 node

dummy → 1
current → 1

list1 → 2 → 4

Step 2:

Compare 2 and 1

Take list2 node

dummy → 1 → 1
current → second 1

list2 → 3 → 4

Step 3:

Compare 2 and 3

Take list1 node

dummy → 1 → 1 → 2

list1 → 4

Step 4:

Compare 4 and 3

Take list2 node

dummy → 1 → 1 → 2 → 3

list2 → 4

Step 5:

Compare 4 and 4

Take list1 node

dummy → 1 → 1 → 2 → 3 → 4

list1 → null

Loop ends.

Attach remaining nodes of list2.

Result:

1 → 1 → 2 → 3 → 4 → 4

--------------------------------------------------

Why Dummy Node?

Without a dummy node:

- Special handling is required for the first node.
- The head of the merged list can be lost.

Dummy node helps:

dummy → 1 → 1 → 2 → 3 → 4 → 4

The actual merged list starts at:

dummy.next

--------------------------------------------------

Mistakes / Learning

- Use list1 != null and list2 != null in the while condition.
- Do not use list1.next != null or list2.next != null.
  Doing so skips the last node and may cause errors.
- The remaining nodes can be attached using a single statement:

current.next = list1;

or

current.next = list2;

- No need to create new nodes.
- Reuse the existing nodes by changing next pointers.

--------------------------------------------------

Edge Cases

Case 1:

list1 = []
list2 = [1,2,3]

Output:

[1,2,3]

Case 2:

list1 = [1,2,3]
list2 = []

Output:

[1,2,3]

Case 3:

list1 = []
list2 = []

Output:

[]

Interview Takeaway

Whenever you need to build or merge a linked list:

Think:
"Can a dummy node simplify head handling?"

Dummy nodes eliminate special cases and make linked list code much cleaner.
