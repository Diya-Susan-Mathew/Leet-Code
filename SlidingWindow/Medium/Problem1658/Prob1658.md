# LeetCode 1658 — Minimum Operations to Reduce X to Zero

## My Solution

```java
class Solution {

    public int minOperations(int[] nums, int x) {

        long totalSum = 0;

        for(int i=0;i<nums.length;i++){
            totalSum += nums[i];
        }

        long requiredSum = totalSum - x;

        if(requiredSum < 0){
            return -1;
        }

        int left = 0;
        int maxLength = -1;
        long currSum = 0;

        for(int right = 0; right<nums.length; right++){

            currSum += nums[right];

            while((currSum > requiredSum) && (left <= right)){
                currSum -= nums[left];
                left++;
            }

            if(currSum == requiredSum){
                maxLength = Math.max(maxLength, right-left+1);
            }
        }

        return maxLength == -1 ? -1 : nums.length - maxLength;
    }
}
```

---

# Intuition

We need to remove elements only from the **left or right end** so that their sum becomes `x`.

Instead of directly finding what to remove, look at what is left.

If:

```text
totalSum = removedSum + remainingSum
```

and we need:

```text
removedSum = x
```

then:

```text
remainingSum = totalSum - x
```

So the problem becomes:

> **Find the longest contiguous subarray whose sum is `totalSum - x`.**

Why the longest? Because everything outside that subarray is removed.

Therefore:

```text
minimum operations
= nums.length - longest remaining subarray length
```

---

# Example

```text
nums = [1, 1, 4, 2, 3]
x = 5
```

Total sum:

```text
1 + 1 + 4 + 2 + 3 = 11
```

Required remaining sum:

```text
11 - 5 = 6
```

Now find the longest subarray with sum `6`:

```text
[1, 1, 4]
```

Length:

```text
3
```

So the number of elements removed is:

```text
5 - 3 = 2
```

Answer:

```text
2
```

---

# Step 1 — Calculate Total Sum

```java
long totalSum = 0;

for(int i=0;i<nums.length;i++){
    totalSum += nums[i];
}
```

This calculates the sum of the entire array.

---

# Step 2 — Find the Required Remaining Sum

```java
long requiredSum = totalSum - x;
```

If:

```text
totalSum = 11
x = 5
```

then:

```text
requiredSum = 6
```

We now need to find a subarray with sum `6`.

---

# Step 3 — Check for an Impossible Case

```java
if(requiredSum < 0){
    return -1;
}
```

Since the problem contains positive numbers, if:

```text
totalSum < x
```

we cannot remove elements whose sum is `x`.

For example:

```text
nums = [1, 2, 3]
x = 10
```

Then:

```text
totalSum = 6
requiredSum = 6 - 10 = -4
```

So the answer is `-1`.

---

# Step 4 — Use Sliding Window

```java
int left = 0;
int maxLength = -1;
long currSum = 0;
```

The current window is:

```text
[left ... right]
```

We move `right` forward to expand the window.

If the sum becomes too large, we move `left` forward to shrink it.

---

# Step 5 — Expand the Window

```java
for(int right = 0; right<nums.length; right++){
    currSum += nums[right];
```

For:

```text
nums = [1, 1, 4, 2, 3]
```

we gradually get:

```text
right = 0 → currSum = 1
right = 1 → currSum = 2
right = 2 → currSum = 6
```

At `right = 2`, the window is:

```text
[1, 1, 4]
```

and its sum is `6`.

---

# Step 6 — Shrink When Sum Is Too Large

```java
while((currSum > requiredSum) && (left <= right)){
    currSum -= nums[left];
    left++;
}
```

Suppose:

```text
requiredSum = 6
window = [1, 1, 4, 2]
currSum = 8
```

The sum is too large, so remove from the left:

```text
remove 1 → sum = 7
remove 1 → sum = 6
```

Now the window is:

```text
[4, 2]
```

with sum `6`.

### Why does sliding window work?

Because all numbers are **positive**.

When `right` moves forward, the sum increases.

When `left` moves forward, the sum decreases.

So if:

```text
currSum > requiredSum
```

we can safely shrink the window.

---

# Step 7 — Store the Longest Valid Window

```java
if(currSum == requiredSum){
    maxLength = Math.max(maxLength, right-left+1);
}
```

The current window length is:

```text
right - left + 1
```

We keep the maximum length because a longer remaining subarray means fewer elements need to be removed.

---

# Step 8 — Calculate the Answer

```java
return maxLength == -1 ? -1 : nums.length - maxLength;
```

If no valid subarray was found:

```text
maxLength = -1
```

so return `-1`.

Otherwise:

```text
minimum operations
= array length - longest subarray length
```

---

# Dry Run

Consider:

```text
nums = [1, 1, 4, 2, 3]
x = 5
```

```text
totalSum = 11
requiredSum = 11 - 5 = 6
```

| `right` | Current window | `currSum` | Action | `maxLength` |
|---:|---|---:|---|---:|
| 0 | `[1]` | 1 | Continue | -1 |
| 1 | `[1,1]` | 2 | Continue | -1 |
| 2 | `[1,1,4]` | 6 | Found | 3 |
| 3 | `[1,1,4,2]` | 8 | Shrink → `[4,2]` | 3 |
| 4 | `[4,2,3]` | 9 | Shrink → sum 5 | 3 |

Finally:

```text
maxLength = 3
```

Therefore:

```text
answer = 5 - 3 = 2
```

# Complexity Analysis

Let:

```text
n = nums.length
```

## Time Complexity

The first loop calculates the total sum:

```text
O(n)
```

The sliding-window loop is also:

```text
O(n)
```

Although there is a `while` loop inside the `for` loop, the solution is **not O(n²)**.

Why?

- `right` moves from left to right at most `n` times.
- `left` also moves forward at most `n` times overall.

So the total pointer movements are:

```text
O(n) + O(n) = O(n)
```

Therefore:

### Time Complexity: `O(n)`

---

# Space Complexity

Only a few variables are used:

```java
totalSum
requiredSum
left
maxLength
currSum
```

No data structure proportional to the input size is created.

### Space Complexity: `O(1)`

---

# Complexity Summary

| Part | Time | Space |
|---|---:|---:|
| Calculate total sum | `O(n)` | `O(1)` |
| Sliding window | `O(n)` | `O(1)` |
| Final calculation | `O(1)` | `O(1)` |
| **Overall** | **O(n)** | **O(1)** |

---

# Why Use `long`?

Your code uses:

```java
long totalSum = 0;
long requiredSum = totalSum - x;
long currSum = 0;
```

This is useful because the sum of many `int` values can potentially exceed the range of an `int`.

Using `long` for the running sums prevents integer overflow in those calculations.

# Important DSA Pattern

The most important transformation to remember is:

```text
Remove minimum elements from ends
                ↓
Find maximum elements that can remain
                ↓
Find longest subarray with sum totalSum - x
                ↓
Use sliding window
                ↓
answer = n - longestSubarrayLength
```

---

# Pattern to Recognize

When a problem has:

- Removal from the left/right ends
- Positive numbers
- A target sum
- A requirement to minimize the number of removed elements

Think:

```text
Minimum removed
       ↓
Maximum remaining
       ↓
Longest valid subarray
       ↓
Sliding Window
```

---

# Final Takeaway

Your solution is a **mathematical transformation + sliding window** solution.

The core idea is:

```text
totalSum - x
```

is the sum that should remain.

Then find the **longest contiguous subarray** with that sum.

Finally:

```text
minimum operations = n - longest subarray length
```

### Final Complexity

```text
Time  → O(n)
Space → O(1)
```

The nested-looking `while` loop does not make the algorithm `O(n²)` because both `left` and `right` move only forward, each at most `n` times overall.
