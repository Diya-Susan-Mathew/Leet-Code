# LeetCode 1051 — Height Checker

## Problem

Students are standing in a line in a given order. `heights[i]` represents the height of the student at index `i`.

The expected order is the students sorted in non-decreasing order of height.

Return the number of indices where the current order differs from the expected order.

---

# Approach 1: Sorting

### Idea

1. Create a copy of the original array.
2. Sort the copied array.
3. Compare the original array with the sorted array.
4. Count how many positions contain different values.

### Code

```java
class Solution {

    public int heightChecker(int[] heights) {

        int count = 0;

        int[] expected = heights.clone();

        Arrays.sort(expected);

        for(int i = 0; i < heights.length; i++){

            if(heights[i] != expected[i]){
                count++;
            }

        }

        return count;
    }
}
```

### How to think about it

The question asks:

> "How many students are standing at a position different from where they would be after sorting?"

So the simplest idea is:

**Original array → Sort a copy → Compare both arrays**

### Complexity

- **Time:** `O(n log n)` because of sorting
- **Space:** `O(n)` for the copied array

---

# Approach 2: Counting Sort / Frequency Counting

## Key Observation

The height values are limited.

According to the problem constraints:

```text
1 <= heights[i] <= 100
```

Instead of sorting the entire array, we can count how many students have each height.

For example:

```text
heights = [1, 1, 4, 2, 1, 3]

Frequency:

1 → 3
2 → 1
3 → 1
4 → 1
```

From these frequencies, we can reconstruct the expected sorted order:

```text
[1, 1, 1, 2, 3, 4]
```

We don't actually need to create this sorted array.

---

## Code

```java
class Solution {

    public int heightChecker(int[] heights) {

        int ans = 0;

        int currentHeight = 1;

        int[] count = new int[101];

        // Step 1: Count the occurrences of each height
        for (int height : heights) {
            count[height]++;
        }

        // Step 2: Compare each student with the expected height
        for (int height : heights) {

            // Find the smallest height that is still available
            while (count[currentHeight] == 0) {
                currentHeight++;
            }

            // Current student is different from expected student
            if (height != currentHeight) {
                ans++;
            }

            // One occurrence of this expected height has been used
            count[currentHeight]--;
        }

        return ans;
    }
}
```

---

# Understanding the Optimized Approach

Suppose:

```text
heights = [1, 1, 4, 2, 1, 3]
```

The frequency array tells us:

```text
Height    Frequency
  1          3
  2          1
  3          1
  4          1
```

Therefore, the expected order is:

```text
[1, 1, 1, 2, 3, 4]
```

But instead of creating this array, we keep track of the next expected height using:

```java
currentHeight
```

Initially:

```java
currentHeight = 1;
```

We look for the smallest height that still has students remaining.

### First student

```text
Actual = 1
Expected = 1
```

No mismatch.

Then:

```java
count[1]--;
```

### Second student

```text
Actual = 1
Expected = 1
```

No mismatch.

### Third student

```text
Actual = 4
Expected = 1
```

Mismatch:

```text
ans = 1
```

Then we consume one expected `1`.

The process continues until every student has been checked.

---

# Why Is This Faster?

### Your approach

You use:

```java
Arrays.sort(expected);
```

Sorting takes:

```text
O(n log n)
```

### Counting approach

The heights are restricted to `1–100`.

So instead of sorting, we count frequencies.

Counting takes:

```text
O(n)
```

Then we scan through the students:

```text
O(n)
```

Finding the next height only moves `currentHeight` forward from `1` to `100`, so this is bounded by the height range.

Overall:

```text
O(n + k)
```

where `k = 100`.

Since `100` is effectively constant:

```text
O(n)
```

---

# Complexity Comparison

| Approach | Time | Space | Main Idea |
|---|---:|---:|---|
| Sorting | `O(n log n)` | `O(n)` | Sort and compare |
| Counting | `O(n + k)` | `O(k)` | Count frequencies |

Here:

```text
k = maximum possible height = 100
```

# Important Pattern to Learn

This problem teaches an important interview pattern:

## "Small Value Range → Think Counting"

Whenever you see constraints like:

```text
1 <= value <= 100
```

or

```text
0 <= value <= 1000
```

ask yourself:

> **"Do I really need to sort this, or can I count the values?"**

This is the idea behind **Counting Sort**.

# Your Approach vs Optimized Approach

Your approach is:

```text
Copy
  ↓
Sort
  ↓
Compare
  ↓
Count mismatches
```

Optimized approach:

```text
Count frequencies
  ↓
Generate expected values mentally
  ↓
Compare while scanning
  ↓
Count mismatches
```

Your solution is **correct and very reasonable**. The optimized solution is mainly exploiting the special constraint that heights are limited to `1–100`.
