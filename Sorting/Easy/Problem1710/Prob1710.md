# Maximum Units on a Truck

**LeetCode Problem:** 1710 — Maximum Units on a Truck  
**Difficulty:** Easy  
**Topic:** Greedy, Sorting  
**Language:** Java

---

## Problem

You are given a 2D integer array `boxTypes` where:

```text
boxTypes[i] = [numberOfBoxes, unitsPerBox]
```

You are also given an integer `truckSize`, which represents the maximum number of boxes the truck can carry.

Each box type contains the same number of units.

Your goal is to **maximize the total number of units** loaded onto the truck.

### Example

```text
Input:
boxTypes = [[1,3],[2,2],[3,1]]
truckSize = 4

Output:
8
```

### Explanation

We should choose:

- 1 box with 3 units → `1 × 3 = 3`
- 2 boxes with 2 units → `2 × 2 = 4`
- 1 box with 1 unit → `1 × 1 = 1`

Total:

```text
3 + 4 + 1 = 8 units
```

---

# Approach — Greedy

The important observation is:

> **Always pick boxes that give the highest units per box first.**

Therefore, we sort `boxTypes` in **descending order of units per box**.

For example:

```text
[[1,3],
 [2,2],
 [3,1]]
```

is already sorted:

```text
units per box:
3 → highest
2
1 → lowest
```

Then we keep filling the truck until:

```text
truckSize = 0
```

or there are no more boxes.

---

## Why Greedy Works

Suppose we have:

```text
Type A → 5 units/box
Type B → 2 units/box
```

If there is space for only one box, choosing Type A gives us:

```text
5 units
```

instead of:

```text
2 units
```

So choosing the highest `unitsPerBox` first can never be worse than choosing a lower-value box first.

This is the **Greedy strategy**.

---

# Java Solution

```java
class Solution {
    public int maximumUnits(int[][] boxTypes, int truckSize) {

        // Sort by units per box in descending order
        Arrays.sort(boxTypes, (a, b) ->
            Integer.compare(b[1], a[1])
        );

        int size = 0;
        int units = 0;
        int remsize = truckSize;

        for (int i = 0; i < boxTypes.length; i++) {

            // If remaining space is smaller than
            // the number of available boxes
            if (remsize < boxTypes[i][0]) {

                size += remsize;
                units = units + remsize * boxTypes[i][1];

                break;

            } else {

                size += boxTypes[i][0];

                units = units +
                        (boxTypes[i][0] * boxTypes[i][1]);

                remsize = truckSize - size;
            }
        }

        return units;
    }
}
```

# Dry Run

Consider:

```text
boxTypes = [[1,3], [2,2], [3,1]]
truckSize = 4
```

### Step 1 — Sort

Sort by `unitsPerBox` in descending order:

```text
[[1,3],
 [2,2],
 [3,1]]
```

### Step 2 — Take first type

```text
Available boxes = 1
Units per box = 3
Remaining truck space = 4
```

Take 1 box:

```text
units = 1 × 3 = 3
remaining space = 3
```

### Step 3 — Take second type

```text
Available boxes = 2
Units per box = 2
Remaining truck space = 3
```

Take both boxes:

```text
units = 3 + (2 × 2)
      = 7

remaining space = 1
```

### Step 4 — Take third type

```text
Available boxes = 3
Units per box = 1
Remaining truck space = 1
```

We can take only 1 box:

```text
units = 7 + (1 × 1)
      = 8
```

Therefore:

```text
Answer = 8
```

# Complexity

### Sorting

There are `n` box types.

Sorting takes:

```text
O(n log n)
```

### Traversing

We visit each box type once:

```text
O(n)
```

### Overall

```text
Time Complexity: O(n log n)
Space Complexity: O(1)
```

Ignoring the space used internally by the sorting implementation.

# Key Pattern to Remember

This is a classic **Greedy + Sorting** problem.

Whenever you see:

- limited capacity
- different values for each item
- you want to maximize total value
- items can be partially selected

Think:

```text
Sort by value
        ↓
Take highest-value items first
        ↓
Stop when capacity is full
```

# Important Takeaway

The main idea is **not** the code.

Remember this:

> **When every box occupies exactly one unit of truck capacity, prioritize the box type with the highest units per box.**

That observation leads directly to the greedy solution.
