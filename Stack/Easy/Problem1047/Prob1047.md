# Remove All Adjacent Duplicates In String

**LeetCode:** 1047 — Remove All Adjacent Duplicates In String  
**Difficulty:** Easy  
**Pattern:** Stack  
**Language:** Java

---

## 1. Stack Approach

### Code

```java
class Solution {
    public String removeDuplicates(String s) {

        Stack<Character> stack = new Stack<>();

        stack.push(s.charAt(0));

        for (int i = 1; i < s.length(); i++) {

            if (!stack.isEmpty() && stack.peek() == s.charAt(i)) {
                stack.pop();
            } else {
                stack.push(s.charAt(i));
            }
        }

        StringBuilder sb = new StringBuilder();

        for (Character c : stack) {
            sb.append(c);
        }

        return sb.toString();
    }
}
```

---

## 2. How the Stack Approach Works

The stack stores characters that have **not yet been removed**.

For every character:

### If it matches the top of the stack

```text
stack.peek() == current character
```

Remove the top:

```text
stack.pop()
```

### Otherwise

Add the current character:

```text
stack.push(currentChar)
```

This automatically handles **chain reactions**.

### Example

```text
s = "abbaca"
```

Process the characters:

```text
a → [a]

b → [a,b]

b → [a]
     ↑
   duplicate removed

a → []
     ↑
   duplicate removed

c → [c]

a → [c,a]
```

Result:

```text
"ca"
```

# 3. Optimized Approach — StringBuilder as a Stack

Instead of:

```java
Stack<Character>
```

we can use:

```java
StringBuilder
```

The last character of the `StringBuilder` behaves like the **top of the stack**.

### Code

```java
class Solution {
    public String removeDuplicates(String s) {

        StringBuilder sb = new StringBuilder();

        for (int i = 0; i < s.length(); i++) {

            char currentChar = s.charAt(i);
            int len = sb.length();

            // Stack is not empty and top matches current character
            if (len > 0 && sb.charAt(len - 1) == currentChar) {

                // Pop
                sb.deleteCharAt(len - 1);

            } else {

                // Push
                sb.append(currentChar);
            }
        }

        return sb.toString();
    }
}
```

---

# 4. Why Does StringBuilder Work Like a Stack?

A stack has two important operations:

```text
push() → add to the top
pop()  → remove from the top
```

`StringBuilder` can perform the same operations.

### Push

```java
sb.append(currentChar);
```

Equivalent to:

```java
stack.push(currentChar);
```

### Peek

```java
sb.charAt(sb.length() - 1);
```

Equivalent to:

```java
stack.peek();
```

### Pop

```java
sb.deleteCharAt(sb.length() - 1);
```

Equivalent to:

```java
stack.pop();
```

So:

```text
Stack<Character>              StringBuilder

push(c)        →              append(c)

peek()         →              charAt(length - 1)

pop()          →              deleteCharAt(length - 1)
```

---

# 5. Why Is StringBuilder Better Here?

`Stack<Character>` stores every character as a **`Character` object** and also has synchronization/legacy overhead.

`StringBuilder` stores characters directly in its internal character array.

Therefore, for this problem:

```text
Stack<Character>
       ↓
Extra object / collection overhead

StringBuilder
       ↓
Direct character storage
```

The `StringBuilder` approach is generally **more memory-efficient** and is a common Java technique for implementing stack-like behavior when the elements are characters.

---

# 6. Complexity

Let `n` be the length of the string.

### Stack solution

```text
Time:  O(n)
Space: O(n)
```

### StringBuilder solution

```text
Time:  O(n)
Space: O(n)
```

The **Big-O space complexity is still O(n)** because the result itself can contain up to `n` characters.

The difference is in the **constant memory overhead**, not the asymptotic complexity.

# 7. Important Pattern

This problem teaches an important Stack pattern:

> **When processing elements from left to right, if the current element conflicts with the most recently kept element, remove the most recently kept element.**

Think:

```text
Current element
       ↓
Compare with previous kept element
       ↓
   ┌─── Same ───→ Remove previous
   │
   └── Different → Add current
```

This pattern appears in many problems involving:

- Adjacent duplicates
- Undo operations
- Parentheses
- Backtracking
- Removing conflicting elements
- Monotonic stacks
